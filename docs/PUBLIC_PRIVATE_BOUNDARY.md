# Optimization chapter: public and restricted evidence

The optimization review publishes a deliberately small numerical account of
reviewed evidence. It supports inspection and table arithmetic without exposing
the private scientific execution tree. A source's SHA identifies particular
bytes; it does not grant access to those bytes or permission to redistribute
external software.

The authority is
[OPTIMIZATION_STORY.json](../data/optimization_story/v001/OPTIMIZATION_STORY.json),
the [claim map](../data/optimization_story/v001/CLAIM_DATA_MAP.tsv),
[provenance](../data/optimization_story/v001/PROVENANCE.json) and
[publication allowlist](../data/optimization_story/v001/PUBLICATION_ALLOWLIST.json).
[The methods guide](OPTIMIZATION_STORY.md) explains the mathematical definitions,
recovery, checkpoints and engineering scope.

## Source identity and access labels

The provenance registry supplies exact source sizes and SHA-256 values. Public
sources use repository paths and URLs pinned to verified baseline
`f5f4784d7cc186ae9cfcacbd97117b5dabbffb30`. Restricted sources use explicit
audit-relative locators with no URL. Those locators explain which reviewed
source supports a claim; they are not public repository files or promised
downloads. Absolute private machine paths and credentials are excluded.

Each claim has a common `status`, a detailed `verification_status`, units,
an exact `source_field` and source-access information. A numerical result can
be physically measured while its source remains restricted. A saved score can
be reaggregated without its missing original prediction vectors. A mathematical
statement can be proved under assumptions without demonstrating predictive
improvement. The two status columns preserve those distinctions.

The optional `data_field` column is section-relative where populated for theory.
Observer/T1 rows identify their source fields and named result tables without
populating that extra locator. The H force-error claim directly names the
existing public prediction file and includes the public reference file as an
additional source; its restricted summary is supplemental evidence.

## The build's publication gate

The chapter builder reads only the committed public aggregate directory. It
does not search private directories, import native scientific software, or
fall back to a missing restricted source. The v001 export pins the five
G1-reviewed file hashes after semantic validation. Rewriting a checksum
manifest alone cannot approve altered evidence categories or unreviewed content.
A later edition requires a newly reviewed bundle and a corresponding gate
update. The allowlist does not hash itself; its exact bytes are bound by the
reviewed edition gate and repository revision.

The full site build and portable review artifact contain public site/data
assets only. The new package excludes native source and executables, private
models/checkpoints, full event journals, replay arrays, design/normal-equation
matrices, pseudopotentials, protected holdout data and private recovery archives.
Relative filenames and checksums may identify excluded evidence without
redistributing it.

Project-owned explanatory prose and aggregate derivatives follow the existing
repository license boundaries. This review does not change the rights to MLIP,
Quantum ESPRESSO, other external scientific programs or their source packages.
It also makes no claim that the full scientific workflow is containerized or
publicly reproducible from the site download alone.

## Recovery does not overwrite history

The original M01 archive was not found in the requested search. Necessary
recovery produced a new diagnostic journal and six replays. Four live-state
results match independently retained historical member hashes and sizes;
S1c/S2q are explicitly new derived states. The S2q physical point targets
`ROW_EXACT_FIXED_D`, separately from high-precision analysis of captured native
K. This is checked replacement evidence for the present diagnostic, not a claim
that the missing original archive or old journal was restored.

The new recovery does not repair the missing historical XI training chronology.
It does not turn the old XI-T P1 `FAIL_STOP_NO_RETRY` into PASS. TERMINAL PBE14
remains a fourteen-score reaggregation because its original prediction CFG is
missing. These limitations are retained in the public payload and beside the
comparison they qualify. Sources `OBS_RECOVERY_LEDGER`, `OBS_XIT_GATE` and
`OBS_XIT_PBE14` give the source identities.

Historical T1 used synthetic configurations and made no real-data fit in its
closure. The later recovery's one real diagnostic fit and six physical replay
processes belong to a separate ledger. Neither establishes a real-data COV
optimizer advantage. The saved-row COV candidate was not physically evaluated
or exported, and T2/DFT/MD/protected-holdout model evaluations were zero in the
new recovery.

**Engineered and checked on synthetic runs. Not yet demonstrated to be a better
real-data optimizer.** PBE14 is development evidence. Independent external
physical validation remains unavailable, and existing `SEED_SENSITIVE` and
`STATIC_APPLICABILITY_FAIL` findings are unchanged.

## Review delivery and production

This work prepares an inspectable branch, a draft pull request and a portable
preview/CI artifact. A local `#optimization` preview is distinguished from the
published production exhibit. The review does not merge, change repository
settings, deploy Pages, create a release or revise existing release tags,
CITATION.cff or DOI records. Actual verification evidence must identify the
tested revision; these scope statements do not substitute for executed checks.
